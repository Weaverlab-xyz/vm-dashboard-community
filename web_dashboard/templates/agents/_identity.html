{# The Identity tab of the Remote Agents page (agents/index.html): the agents' pinned signing audience, and the dashboard's own SPIFFE identity. Both answer to the `agents` scope -- GET /api/agents/audience and GET /api/spiffe-identity are agents:read, DELETE /api/agents/audience and POST /api/spiffe-identity/check-issuer are agents:write -- but until this tab they were shown only inside Settings → Integrations, which is admin-only because it is instance configuration. A role granting `agents` reached the Agents page (PR #1144) and still could not see why enrolment codes were refused. The Settings drawers keep their copies beside the fields that configure these values (Public base URL, the SPIFFE audiences); this tab is the read-and-repair view. Write buttons show on $store.auth.can('agents', 'write'); the routes are the control. Self-contained like the other tab partials -- markup and factory in this one file (see the hub's note on why). #}

You cannot see the agents' identity

This tab needs the agents permission.

Signing audience

The address every agent signs its requests against. It is pinned by the first enrolment code and never moves on its own, so a corrected Public base URL leaves enrolled agents working and refuses new codes until the two agree.

The dashboard's SPIFFE identity

Short-lived tokens the dashboard presents to a cloud instead of a stored key, and the issuer the cloud fetches its keys from. How it works.

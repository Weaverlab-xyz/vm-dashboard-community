{# The Config Routes tab of the Remote Agents page (agents/index.html), backed by /api/connections/config-mgmt-routes. WHICH AGENT EXECUTES a Config-Management run against an address range — as opposed to which agent brokers the hypervisor the target was discovered through. Those are the same agent by default, and this tab exists because they cannot always be: VMware Workstation's vmrest binds 127.0.0.1 with no bind-address option, so the brokering agent must run ON the Windows host under Docker Desktop, whose WSL2 VM can reach no VMware vmnet. The agent that can read the inventory is then structurally unable to reach the VMs in it. A RANGE, NOT A CONNECTION, and that is the whole design: reachability is a property of the network. One vmrest connection routinely reports guests on several vmnets at once, so a per-connection executor could not express "that segment is reachable from there, this one is not". Matching is longest-prefix-first like a routing table, and one range may name only one agent — the service refuses a duplicate rather than guessing. IT DESIGNATES WHO RUNS, NEVER WHAT IS RUN AGAINST. There is no host, port, credential or transport on this form and there must never be one: the address stays pinned to one the discovering agent itself reported. See services/config_mgmt_route_service. Self-contained, and that is required of it rather than tidy: the markup and the Alpine factory it names live in this one file, which is what tests/test_template_scripts.py and tests/test_templates_parse.py check of any template carrying an x-data. #}

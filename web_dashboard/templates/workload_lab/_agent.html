{# Workload Lab → Agent. The non-human principal that CONSUMES what the other four tabs build. Backed by /api/agentcell. IT BELONGS HERE RATHER THAN ON A PAGE OF ITS OWN, and the reason is the whole point of the tab: every other tab on this page answers "how does a machine get a credential", and every one of them is answered in the abstract until something actually holds one. This tab is that something. It attests to the SPIRE tab's trust domain, and it can be made answerable for the Cloud tab's lease, the Kubernetes tab's token or the Certificate tab's identity — so the four mechanisms stop being four demos and become one. SIX THINGS HERE ARE LOAD-BEARING AND EASY TO MISTAKE FOR DECORATION: * IDENTITY AND AUTHORIZATION ARE TWO THINGS, and this tab must never draw them as one. The worker attests to SPIRE and gets an SVID — that is WHO IT IS, and it holds nothing. It calls /mcp with a Personal Access Token — that is WHAT IT MAY DO. Nothing mints one from the other (api/mcp_server takes a Bearer PAT and has no mTLS path), and the closing beat of the demo is exactly that gap: revoke the token and the worker is still who it was and may no longer do anything. * THE TOKEN IS SHOWN ONCE. Same contract as api/tokens.create_token — the row keeps the id, the name and the expiry, never the secret. The modal that shows it is therefore the only chance, and it says so. * A LINK IS NOT ALWAYS A CAPABILITY, and all three shipped tabs happen to be one today. `cloud` used to be accountability only; it is a capability now, because the worker mints from Workload Credentials itself (`--cloud-episode`) rather than being handed anything by this dashboard. `linkKind` stays a THREE-state read anyway: the question is answered server-side, and a reader whose /options call 403'd must not have the page guess on their behalf. Rendering the two kinds alike is this feature's headline failure mode in one direction and the Kubernetes tab's in the other, so the picker states which it is BEFORE the link is made. * THE THREE CAPABILITIES REACH DIFFERENT AUTHORITIES, which is the distinction that replaced the old one. `kubernetes` and `certificates` reach PASSWORD SAFE holding nothing, so retrieval is a recorded request that can require approval. `cloud` reaches WORKLOAD CREDENTIALS directly and there is no vault in the chain, because WC mints rather than releases — so no approval exists to wait on, and the issuance is BILLED. A page that said "reaches Password Safe holding nothing" over a cloud link would be describing the wrong mechanism. * A CAPABILITY IS NOT ALWAYS AN EPISODE THIS DASHBOARD CAN OPEN, and conflating the two is what made the Request-access button lie. TWO of the three are spendable with NO episode route here — both are one shot on the host, `mcp_agent.py --cert-episode` and `--cloud-episode` — so a button gated on `spendable` posted a certificate link at /k8s-request, which looked it up in the token table, missed, and refused it as "the linked Kubernetes token no longer exists. Unlink and relink." A valid link, accused of having lost its credential, with the remedy pointing at the one thing that was right. `episodeMechanism` is the gate now, and it is resolved server-side for the same reason `linkKind` is. * THE DASHBOARD DOES NOT WATCH THE INSTALL. The two playbooks are runs the operator makes; nothing writes `stages_done`, so this tab shows the install as a checklist of what YOU do and names `journalctl -u mcp-agent` as the record. A progress bar here would be a field that is structurally always empty, which reads as "nothing happened yet" on a cell where plenty did. * REVOKE IS NOT UNINSTALL, and the confirm says so. The worker keeps running and keeps attesting; its next poll is refused. Hiding that behind a teardown would remove the only thing worth watching. #}

Two things, and nothing bridges them

Its identity is a SPIFFE SVID it re-attests on every loop, holding nothing at rest. Its authorization is a Personal Access Token bounded by the RBAC of the user you mint it against. The SVID does not authenticate to /mcp — closing that would need the Password Safe SPIFFE SVID plugin, whose configuration question is still unresolved. So the cell shows both halves and names the gap rather than implying a bridge.

That gap is the demo: revoke the token and the worker is still who it was, and may no longer do anything.

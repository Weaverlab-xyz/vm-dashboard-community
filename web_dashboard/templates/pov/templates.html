The POV page can only build FROM a template. This page is where one comes from, and the reason it exists is in three parts: Build — clone a base template into a scratch environment, prepare it, and save it back as a new template. A template is immutable on every lab platform, so authoring is always instantiate → change → bake, never edit in place. The scratch environment is created, used and reaped inside one job. Verify — check a template somebody else authored against the template contract, without building anything. This is the question an SE has about the existing catalogue — "would a POV from this actually work?" — and before this page there was no way to ask it. Blueprint — a saved POV recipe. Not a Skytap object: the eleven fields the POV create form asks, under one name, so building the next POV of a known kind is one choice instead of eleven. The contract report is shown per check rather than as one verdict. "no broker VM" and "the broker is on a manual network" have different fixes, and collapsing them is how somebody rebuilds the wrong thing — the same rule the POV page's Broker column follows. Warnings never block a bake. "No Windows guest" means this template cannot host a Resource Broker, which is a correct description of a PRA-and-Entitle POV, not a defect. Only a `fail` stops the build, because a fail means the template cannot run a POV at all. The install script is offered on EVERY build, not just a failed one. An operator whose network has no route to a NAT-ed high port needs it as the primary route and should not have to fail once to find out it exists. #} {% block content %} {# The platform toggle decides which tabs exist, because the two kinds of platform author a template in unrelated ways and showing both at once was the confusion this page had: with AWS toggled it warned that "AWS cannot save an environment back as a template" directly above a working AWS template, and listed Skytap bakes under "Builds". Skytap — Build a template + Build history: the bake, which only a platform with `template_authoring` can do. a cloud — Templates: the topology spec the dashboard holds, because no public cloud holds a template object at all.

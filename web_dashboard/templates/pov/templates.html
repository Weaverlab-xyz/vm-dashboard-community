{% extends "base.html" %} {% block title %}POV Templates{% endblock %} {# Where the templates a POV is built from get authored. The POV page can only build FROM a template. This page is where one comes from, and the reason it exists is in three parts: Build — clone a base template into a scratch environment, prepare it, and save it back as a new template. A template is immutable on every lab platform, so authoring is always instantiate → change → bake, never edit in place. The scratch environment is created, used and reaped inside one job. Verify — check a template somebody else authored against the template contract, without building anything. This is the question an SE has about the existing catalogue — "would a POV from this actually work?" — and before this page there was no way to ask it. Blueprint — a saved POV recipe. Not a Skytap object: the eleven fields the POV create form asks, under one name, so building the next POV of a known kind is one choice instead of eleven. The contract report is shown per check rather than as one verdict. "no broker VM" and "the broker is on a manual network" have different fixes, and collapsing them is how somebody rebuilds the wrong thing — the same rule the POV page's Broker column follows. Warnings never block a bake. "No Windows guest" means this template cannot host a Resource Broker, which is a correct description of a PRA-and-Entitle POV, not a defect. Only a `fail` stops the build, because a fail means the template cannot run a POV at all. The install script is offered on EVERY build, not just a failed one. An operator whose network has no route to a NAT-ed high port needs it as the primary route and should not have to fail once to find out it exists. #} {% block content %}

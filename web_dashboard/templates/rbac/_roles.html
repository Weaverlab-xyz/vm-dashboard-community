{# Access roles -- the Roles tab of the RBAC page. A role is a named permission map that the Users and Groups tabs assign. This tab is where one is created, cloned, edited and, most usefully, where "who holds this?" is answered -- the question that previously meant opening every user in turn. Macro imported here, not inherited from the container -- see the note in _users.html. TWO deliberate differences from the other two tabs' grids, both of which look like omissions and are not: * NO "Full access (unrestricted)" checkbox. That escape hatch stores {} , and on a USER an empty map means unrestricted. A role whose map were empty would therefore hand every assignee every permission in the dashboard, now and for every scope added in future -- the exact opposite of what someone building a restricted role is doing. The server refuses it too (role_service.validate_role_permissions). "Everything" is spelled with the Administrator role, which is auditable. * A BUILT-IN OFFERS NO EDIT CONTROL AT ALL, rather than a disabled grid. 31 rows x 4 disabled checkboxes invites "why can't I tick this?" and the grid has no room to answer; and a rule enforced by the absence of a control cannot be defeated by a stale :disabled binding. Clone is the supported path and is one click. #} {% from "partials/permission_matrix.html" import permission_matrix %}

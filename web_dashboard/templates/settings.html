MCP Server

Connect any MCP-compatible AI client (Claude Desktop, Claude Code, Cursor…) to this dashboard. The server is mounted at /mcp and uses a Personal Access Token for auth.

  1. Create a Personal Access Token in Settings → Security Keys → API Tokens (or /tokens).
  2. Copy the token — it starts with vmcli_.
  3. Add the following block to your MCP client config and replace the placeholder:
{
  "mcpServers": {
    "vm-dashboard": {
      "url": "",
      "headers": {
        "Authorization": "Bearer vmcli_<your-pat-here>"
      }
    }
  }
}

Enable MCP Server under Integrations first — the endpoint returns 404 while it is off. Tools: dashboard_summary, list_jobs, get_job, list_inventory, list_ec2_instances, list_azure_vms, list_gcp_instances, list_oci_instances, list_amis, list_vms, list_containers, list_databases, list_k8s_clusters, list_functions, list_expiring, config_drift, list_agents, cost_summary, secret_staleness. All tools are read-only, and each returns only what the token's owner can see in the UI — a token belonging to a non-admin sees that user's workstreams, not the estate.

{# Three free hexes, which the eight presets deliberately are not. They work because ui_theme resolves them to hand-written CSS classes rather than to Tailwind utilities -- see the header of templates/_brand_css.html for why that distinction is what makes an arbitrary colour possible here at all. All three or none: the API returns 422 on a partial set, because twenty-one chrome slots cannot be derived from one colour without inventing the other twenty. #}

Paste the hex values from the customer's brand guide. All three are required.

{# The TEXT box is the primary affordance and the bound one: a brand guide hands you "#FF5400", and typing it beats hunting for it on a colour wheel. The colour well is deliberately NOT x-model. An input[type=color] coerces any value it cannot parse to #000000, so two-way binding would rewrite a half-typed hex to black on every keystroke and make the text box unusable. #}

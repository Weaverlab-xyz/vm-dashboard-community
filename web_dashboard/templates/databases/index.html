Provisioning needs a Terraform module, so it's cloud-only; registering needs only somewhere to reach. Backed by /api/databases (gated by cloud_database_enabled), and the delete verb follows source — a registered row is deregistered, not destroyed. The "Register in Entitle" button is additionally gated on d.entitle_viable, which is false for two kinds of row: a REGISTERED database (no provisioning credential to hand the connector) and managed SQL Server (Cloud SQL / RDS-standard / Azure SQL Database can't grant the sysadmin/CONTROL SERVER its connector needs). See _entitle_viable in cloud_database_service.py — the API rejects the same rows with a 400, so hiding the button is belt-and-braces. It is ALSO gated on !d.adapter_fn_id, because it is not the same integration as the db_grant function beside it: this one is Entitle's own connector through the shared agent, which on MySQL assigns standing roles rather than minting accounts. Two integrations against one database is the confusing case, so a row offers whichever of the two is not already there. #} {% block content %}
